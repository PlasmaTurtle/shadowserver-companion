# Shadowserver Eclipse — Notification Review

The 0.9.97 review follows a notification from case creation through its five
sections, freezing, certification, delivery records and closing report. The focus
is accurate, readable recipient documents and fewer interruptions while preparing
them. Original imports and existing certified packages remain unchanged.

## Recipient documents

New Introduction pages use **Shadowserver - Cybersecurity Vulnerability
Notification** and display the notification date. Missing severity is neutral,
and source-derived severity is identified as such in the editor. Revised pages
use explicit layout revisions so previously frozen sections retain their wording.
Existing drafts can adopt the current presentation through the section guards.

PDF and Word output share the same section models. The builder's Closing section
uses the exported resource groups and sign-off, including the notification's saved
office details. Published CVE descriptions and scores remain sourced records;
internal outreach temperature remains a discreet symbol in recipient documents.

Word document properties now use the export snapshot's timestamp, sender and
revision. The library template's 2013 dates and generated-by description are
removed. An unknown export timestamp remains absent; it is not substituted with
the notification date or an invented time.

## Data and editing

Finding-value inputs, narrative preview and save validation now use the same
normalized grouping. This fixes rejected edits when the reported software version
is in `component_version`, or the case covers only selected finding conditions.
Original source columns remain intact.

The current cover excludes observations retained only as historical attribution
support from its highlighted asset, dates, counts and product summary. Those
observations remain available in the supporting evidence.

Adopting a changed entity mailing address respects both Introduction and
Attribution freezes. Historical notification views use their saved snapshot and
show a single readiness result per section.

Evidence uploads, evidence inclusion changes, Library text adoption and entity
adoption discard obsolete screen responses and preserve edits made while the
request is running. Switching notifications cannot let a late result replace the
new notification's draft.

## Evidence and supporting records

The evidence reader keeps product/version pairs distinct and presents local NVD
records with their CVE identity, status, dates and description. The revised compact
appendix shows software `component_version` separately from protocol version;
previous appendix layouts remain available for historical drafts. Short records
stay on one page when they fit; long records continue across pages.

Package assembly copies the same source bytes it verified, avoiding a second
unverified read. Missing optional contact evidence is represented as unavailable.
Certified file hashes and source records continue to be checked before publication.

## Verification

`VALIDATION.md` records the final automated results and render inspection. The
validation archive includes representative synthetic reports and the independent
review findings. Synthetic fixtures are explicitly labeled and do not represent
real organizations or exposures.

A synthetic workspace certified with actual 0.9.96 code is opened through 0.9.97
to check stored files, frozen sections and case records. This is distinct from
Windows acceptance of the changed release. The operator has confirmed 0.9.96
works on Windows; the new installer retains the existing installation identity.

## Template scope

The existing body copy is written for USSS/Charlotte outreach. Agency, Department
and Office settings affect sender/header fields but do not create a reviewed
body template for a different agency. The review identified this mismatch for
other-agency use; a configurable, versioned organization template remains separate
work. This pass does not silently generalize government authority or liability
statements merely by substituting an agency name.
