# 0.9.95 — Observatory: approach and resolve

The Dark Matter Field is the default entry into Observatory. Organizations have
stable spatial identities, with distinct asset marks, observation-density halos,
and separate internal priority markers. Selected relationships become prominent;
unrelated structures recede. The existing eclipse artwork remains the background,
with compact instruments and a readable floating selection panel.

## One object, multiple views

Selecting an object first identifies it. Contextual actions then approach it and
open its matching Locations, Products, Organizations, Assets/Findings or History.
These actions retain the existing selection filters. Products are an actual scoped
breakdown, not a jump into an unrelated Library search. The traditional Atlas,
Pulse and Records views are also directly accessible. An explicit traditional
view preference can be remembered.

The short camera approach and data retrieval run together. A fast response waits
for the approach to complete; a slower response shows loading after the approach.
Reduced motion skips travel. New navigation, selection, filtering, or return
interrupts the journey without permitting a late response to replace the new view.
Return to Field restores the saved scope, selection and camera position.

Keyboard users can browse named objects, use contextual controls, and inspect the
same paged Records. Canvas bracket keys select objects; Enter focuses. Advanced
instruments and observation-history controls are collapsible.

## Consistent meaning

All visible projections share a scoped response and revision. The relationship
field, map, timeline, records and counts no longer combine different queries or
background revisions. Product Reset replaces the entire scope. Explicit entity
and product links do not inherit unrelated saved filters.

Historical selection uses an observation from the selected period, retaining its
endpoint and source provenance. Current workflow and current catalog risk are
identified separately from historical observation facts. A new CVE on a host does
not inherit delivery of an older condition. Risk filters apply to the selected CVE.
Intake-selected product/version fields are reused, and equal version strings
without meaningful product context do not create a shared-software connection.

Findings, assets, source observations and distinct observation days have separate
counts. Repeated deliveries do not create density. Genuine repeat observations
strengthen the existing density halo rather than creating extra finding marks.
Unadmitted context remains distinguishable from approved findings. The density
bands remain: up to 50 normal, 51–200 yellow, 201–1,000 red, above 1,000 purple.

Atlas remains a projection of reported geography. A reported city is an approximate
area and must not be treated as a verified organization or equipment address.
Field distance indicates arrangement, not geographic proximity or network traffic.
Pulse uses recorded observation dates; a dense history alone is not a claim that
risk has increased.

## Retrieval and responsiveness

A bounded, revision-aware cache reuses the local canonical projection. Filtering
and exact counts occur before visual limits. Graph and map summaries are bounded;
matching Records are paged, and evidence is retrieved on demand. Records pages
can reuse the current revision without retransmitting the whole visual field.
Changes to working data or local intelligence invalidate the cached read model.

Atlas reuses density/support summaries during pan and hover. It does not recount
all historical observations for ordinary pointer movement. Cancellation of source
evidence and obsolete requests no longer becomes a false timeout message.

## Scope and acceptance

This pass changes Observatory and its verification. It does not requalify imports,
rewrite original evidence, alter certified notifications, change agency scoring,
or add external telemetry calls. The existing intake, entity, catalog, scheduling
and notification features remain in place. No data-schema migration is introduced.

See VALIDATION.md for measured results and HOME_VALIDATION.md for Windows visual,
input and installation acceptance. The build remains unstable until that native
acceptance is completed.
